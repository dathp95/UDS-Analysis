Đây là bộ **Coding Skills / Engineering Guidelines** mà mình nghĩ rất phù hợp với dự án **V-VECTOR** của bạn. Mình đã tổng hợp từ những gì hai anh em đã thống nhất trong quá trình phát triển. Nếu sau này đưa cho Codex hoặc AI khác, chất lượng code sẽ đồng đều hơn rất nhiều.

---

# V-VECTOR Python Development Skills

## 1. General Principles

* Ưu tiên **Clean Code**, dễ đọc hơn code ngắn.
* Tuân thủ **SOLID**, đặc biệt là **Single Responsibility Principle (SRP)**.
* Không viết code "thông minh" nhưng khó hiểu.
* Luôn ưu tiên khả năng bảo trì hơn tối ưu sớm.
* Mỗi class chỉ có **một trách nhiệm**.
* Mỗi widget chỉ thực hiện **một chức năng UI**.
* Không duplicate code, luôn ưu tiên tái sử dụng.

---

# 2. Function Rules

## Một hàm chỉ làm một việc

✔ Đúng

```python
def _load_data()

def _connect_signals()

def _setup_ui()

def _write_json()
```

❌ Sai

```python
def setup_everything():
```

---

## Hàm ngắn

Ưu tiên

```text
10~20 dòng
```

Tối đa

```text
30 dòng
```

Nếu vượt quá

↓

Tách hàm.

---

## Không lồng nhiều tầng

Không nên

```python
if:
    for:
        if:
            while:
```

Tối đa

```text
2 tầng
```

---

## Tên hàm rõ nghĩa

Ví dụ

```python
_load_vehicle_json()

_load_ecu_json()

_write_json()

_create_panel()
```

Không dùng

```python
process()

run()

do()

handle()
```

# 5. Layer Rules

## Model

Chỉ chứa dữ liệu.

Không có business logic.

---

## Repository

Chỉ đọc/ghi dữ liệu.

Ví dụ

```python
load()

save_ecu()

delete_ecu()
```

Không được import

```python
QWidget
```

Không được biết GUI.

---

## Service

Business Logic.

Ví dụ

* Validate
* Parse
* Check duplicate

Không đọc UI.

---

## Controller

Điều phối.

Không parse JSON.

Không tạo Widget.

---

## GUI

Chỉ hiển thị.

Không xử lý business logic.

---

# 6. UI Rules

Mỗi widget đều có cấu trúc giống nhau.

```python
class XXXWidget:

    __init__()

    _setup_ui()

    _connect_signals()

    _load_data()

    # Public

    fn_xxx()
```

---

Không viết UI trong constructor.

Không viết signal trong `_setup_ui()`.

---

# 19. Code Review Checklist

Trước khi hoàn thành một feature, AI cần tự kiểm tra:

* Hàm có chỉ làm **một việc** không?
* Hàm có dài quá 30 dòng không?
* Có đoạn code bị lặp không?
* Có đặt tên rõ nghĩa không?
* Có đúng tầng kiến trúc (GUI → Controller → Service → Repository → Model) không?
* Có hardcode chuỗi, màu sắc hoặc đường dẫn không?
* Có thể tái sử dụng ở nơi khác không?
* Có cần thêm test cho thay đổi này không?

# 20. Nguyên tắc quan trọng nhất của dự án

> **Luôn ưu tiên kiến trúc sạch hơn là hoàn thành tính năng nhanh.**

Một tính năng có thể mất thêm vài giờ để thiết kế, nhưng nếu kiến trúc tốt thì các phiên bản V3, V4 và V5 sẽ phát triển nhanh hơn rất nhiều, ít phát sinh lỗi và dễ bảo trì. Đây cũng là triết lý mà chúng ta đã áp dụng xuyên suốt khi xây dựng V-VECTOR.
