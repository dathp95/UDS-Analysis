# PROJECT: UDS SecurityAccess 0x27 – Seed/Key DLL Integration

## 1. Mục tiêu

Xây dựng ứng dụng Python giao tiếp với ECU qua CAN/ISO-TP, sử dụng thư viện `udsoncan` để thực hiện SecurityAccess (`0x27`).

Ứng dụng phải sử dụng hàm `GenerateKeyEx` từ thư viện `seedkey.dll` để tính Security Key dựa trên Seed nhận được từ ECU.

Yêu cầu chương trình có cấu trúc rõ ràng, dễ mở rộng, có logging chi tiết và xử lý lỗi đầy đủ.

## 2. Công nghệ sử dụng

- Python 3.11+
- `udsoncan`: Xử lý giao thức UDS.
- `python-can`: Giao tiếp CAN.
- `can-isotp`: Xử lý ISO-TP.
- `ctypes`: Tích hợp native DLL.
- `logging`: Ghi log giao tiếp.
- `pytest`: Unit testing.

Hệ điều hành mục tiêu: Windows 10/11.

## 3. Cấu hình CAN

Cho phép cấu hình các tham số:

| Parameter | Default |
|---|---|
| CAN Interface | pcan |
| CAN Channel | PCAN_USBBUS1 |
| CAN Bitrate | 500000 |
| Tester TX ID | 0x7E0 |
| Tester RX ID | 0x7E8 |
| Addressing Mode | Normal 11-bit |
| UDS Timeout | 3 seconds |
| Security Level | 0x01 |
| DLL Path | C:\SeedKey\seedkey.dll |

Không hardcode các giá trị này trong logic xử lý.

Hỗ trợ cấu hình qua CLI hoặc file JSON.

## 4. Quy trình SecurityAccess

Chương trình thực hiện theo trình tự:

### STEP 1 – Diagnostic Session

Tester gửi:

`10 03`

ECU phản hồi thành công:

`50 03 ...`

Cho phép bỏ qua bước này bằng cấu hình `skip_session`.

### STEP 2 – Request Seed

Tester gửi:

`27 01`

ECU phản hồi ví dụ:

`67 01 12 34 56 78`

Chương trình phải:

- Kiểm tra Positive Response.
- Xác nhận subfunction phản hồi là `0x01`.
- Trích xuất Seed dưới dạng `bytes`.
- Không giả định Seed luôn có độ dài 4 byte.
- Xử lý trường hợp Seed toàn byte `00` theo trạng thái bảo mật của ECU.

### STEP 3 – Generate Key bằng GenerateKeyEx

Sử dụng hàm:

`GenerateKeyEx`

Được export từ:

`seedkey.dll`

**Yêu cầu quan trọng:**

Trước khi triển khai, kiểm tra giao diện DLL thực tế.

Xác định:

- DLL là 32-bit hay 64-bit.
- Calling convention: `cdecl` hoặc `stdcall`.
- Tên hàm export thực tế.
- Kiểu dữ liệu và thứ tự các tham số.
- Quy ước mã trả về.
- Cách cấp phát bộ nhớ cho Key.
- Cách xác định độ dài Key.
- Có cần truyền Security Level hay không.
- Có cần truyền Variant hoặc các tham số bổ sung hay không.

Một dạng chữ ký `GenerateKeyEx` có thể gặp trong các thư viện Seed/Key là:

```c
int GenerateKeyEx(
    const unsigned char* ipSeedArray,
    unsigned int iSeedArraySize,
    unsigned int iSecurityLevel,
    const char* ipVariant,
    unsigned char* iopKeyArray,
    unsigned int iMaxKeyArraySize,
    unsigned int* oActualKeyArraySize
);
```
Đây chỉ là chữ ký tham khảo. Không được mặc định DLL thực tế sử dụng chữ ký này.

Tạo module:

`seedkey_provider.py`

Trong đó có class:

`SeedKeyProvider`

Các phương thức dự kiến:

```python
class SeedKeyProvider:

    def __init__(self, dll_path, variant=None):
        ...

    def generate_key(self, seed: bytes, level: int) -> bytes:
        ...
```

Yêu cầu:

- Validate Seed.
- Validate Security Level.
- Validate Key Buffer.
- Kiểm tra kết quả DLL.
- Trả về Key dưới dạng `bytes`.
- Không thay đổi Seed nhận được.
- Không tự tạo thuật toán Seed/Key thay thế.
- Không gọi DLL nếu chưa xác minh ABI.

Nếu thiếu thông tin về chữ ký hàm, dừng ở bước xác minh và yêu cầu bổ sung thông tin thay vì đoán.

### STEP 4 – Send Key

Sau khi DLL trả về Key hợp lệ:

Tester gửi:

`27 02 + KEY`

Ví dụ:

`27 02 AA BB CC DD`

Security Level gửi Key phải tương ứng với Request Seed.

Ví dụ:

| Request Seed | Send Key |
|---|---|
| 27 01 | 27 02 |
| 27 03 | 27 04 |
| 27 05 | 27 06 |

### STEP 5 – Verify Response

Nếu ECU trả về:

`67 02`

Hiển thị:

`SecurityAccess SUCCESS`

Nếu ECU trả về Negative Response, ghi log mã lỗi và dừng quy trình.

Không tiếp tục gửi Key khi chưa xử lý lỗi.

## 5. Xử lý Negative Response

Hỗ trợ tối thiểu:

| NRC | Description |
|---|---|
| 0x12 | SubFunctionNotSupported |
| 0x13 | IncorrectMessageLengthOrInvalidFormat |
| 0x22 | ConditionsNotCorrect |
| 0x24 | RequestSequenceError |
| 0x31 | RequestOutOfRange |
| 0x35 | InvalidKey |
| 0x36 | ExceedNumberOfAttempts |
| 0x37 | RequiredTimeDelayNotExpired |
| 0x78 | ResponsePending |

Yêu cầu:

- Không tự động thử nhiều Key khi nhận `0x35`.
- Không retry SecurityAccess khi nhận `0x36`.
- Tôn trọng thời gian chờ của ECU khi nhận `0x37`.
- Xử lý `0x78` theo cơ chế timeout của UDS.
- Không bỏ qua Negative Response.

## 6. Logging

Ghi log theo từng bước.

Ví dụ:

```text
[INFO] CAN interface initialized
[INFO] Connected to ECU

[TX] 10 03
[RX] 50 03 00 32 01 F4

[TX] 27 01
[RX] 67 01 12 34 56 78

[INFO] Security Level: 0x01
[INFO] Seed Length: 4
[INFO] Seed: 12 34 56 78

[DLL] Calling GenerateKeyEx
[DLL] GenerateKeyEx completed
[DLL] Key Length: 4
[DLL] Key: AA BB CC DD

[TX] 27 02 AA BB CC DD
[RX] 67 02

[SUCCESS] SecurityAccess unlocked
```

Các giá trị chỉ để minh họa.

Hỗ trợ tùy chọn ẩn Seed và Key trong log để tránh lộ dữ liệu bảo mật.

Phân biệt UDS payload với CAN frame thực tế. Nếu log chỉ chứa payload thì phải ghi rõ là UDS payload.

- Đọc cấu hình.
- Kiểm tra tham số.
- Khởi tạo các module.
- Thực thi chương trình.
- Hiển thị kết quả.
